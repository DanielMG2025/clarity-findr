# Architecture rules
- Every route is wrapped by AccessGate; verify identity with getUser and current_user_has_access on loads/navigation/focus, with admin bypass enforced in the database. Keep access-list reads/writes admin-only and magic-link credentials confined to admin responses and same-origin redemption.

- Keep `/report` and `/summary` as read-only aggregations of existing master-record, journey, evidence, pricing, and regulatory outputs so printed figures never diverge from patient pages.

- Both patient reports consume the shared `patientNarrative` presentation helper (it takes the active language and builds each language's prose from the same inputs) so their opening paragraphs cannot drift; keep it read-only.

- Localize display text through the context-aware JSX presentation boundary and exact-copy dictionaries in `src/i18n`; this keeps persisted form values, routes, clinical records and engine outputs untouched. Never mutate React-owned DOM text for translation. Basics guide short copy (titles, hooks, summaries, steps, FAQs, sources) is translated as exact-copy keys in `src/i18n/education.es.ts` and rendered through explicit `t()`; the long "In depth" bodies are stored bilingually as `body_en`/`body_es` in `src/modules/education/depth.*.ts` because dictionary lookup is fragile for paragraphs, and text passed through `AutoGlossary` must be localized with `t()` first because it splits raw strings.

- Learn pills are read from the `pills` table via `usePublishedPills`, which falls back to the static seed in `src/modules/content/pills.ts`, so /descubre never renders empty; writes are gated by the `admin` role in `user_roles` (RLS + `has_role`).

- Forum listening uses active database-configured RSS sources, neutral thematic intake and structured metadata only; manual admin-only ingest/distil reuse existing tables, with item-date freshness and validated support IDs. /descubre reads published topics and an authorized aggregate source count, never the admin-only source configuration.
- `/descubre` is the single general content hub (anchored sections: conversation, pills, Basics guides, scientific library, voices); `RESOURCES.kind` splits institutions (library) from creators/communities (voices). `/aprende` redirects to `/descubre#basicos` while `/aprende/:slug` stays the article route. `/library` stays in the case-tool area because `/sources` and the patient sidebar link to it as the evidence behind the orientation.
- The landing `/` is a two-door fork (/descubre and /situacion as equals, /demo tertiary); its "hot this week" strip reuses `usePublishedTopics` read-only, so it never shows unpublished or non-week topics.
- The patient route (`intent.goal`: preserve/treatment/unsure) is chosen at /situacion entry and only tailors framing and example cases; choosing "preserve" maps to the existing `social_freezing` treatment interest so engines stay unchanged until a dedicated preservation engine exists.
- Engine/journey outputs (factors, plans, legal verdicts, citations, price notes) stay English in the engines and are localized at presentation by `src/i18n/journey.es.ts` (exact keys plus patterned sentences for ages, counts and countries), so engines and tests never depend on language.
- Example cases are `DEMO_PATIENTS` seeds kept inside the engine vocabulary (unmodelled routes like ROPA, tandem, embryo donation or surrogacy map to the closest `treatment_interest` and are explained in the story); the "Legal case" badge comes from the regulatory engine, and a presentation-only marker (`exampleCase.ts`) frames reports as the example's recommendation until "Study your own case" resets the record.
- `/demo` filters read only the curated `treatment_tag`/`situation_tags` on each seed (fixed vocabulary in `exampleCaseTags.ts`, kept in sync with `deriveExampleTags` by a test); engines never read them, so tagging can evolve without touching clinical logic.
- Beta feedback lives in `beta_feedback`; the floating `FeedbackWidget` mounts inside `AccessGate` (never on the gate page or `/widgets/*` embeds), and a BEFORE INSERT trigger stamps email, tester segment (from `allowed_users`) and `new` status server-side because testers cannot read the access list. Review/updates/deletes are admin-only at `/admin/feedback`. Voice notes go to the private `beta-feedback-audio` bucket under `<user_id>/` (storage policies: own-folder upload/read/delete, admin read/delete all), are played only via signed URLs, and the insert trigger rejects an `audio_path` outside the sender's folder; a row needs text or audio, voice-only rows store an empty message. Team replies live in `admin_reply` (admin-only writes; a BEFORE UPDATE trigger stamps `admin_reply_at`), and senders read their own rows by `user_id` or session email. The `/admin` entry lives only in `MainNav` and the header `SessionChip`, both rendered only when `useAdminSession` (`has_role`) confirms admin; the chip names the session from the access list when readable, else profile name or email local part.
- Example cases never overwrite the user's own record: `openExampleCase` parks the own record in `fc:mpr-own` before loading a seed, and `/situacion` calls `restoreOwnCase` on entry so the personal flow only shows the user's own data (or empty); `startOwnCase` is the explicit empty restart.
- The by-country regulation comparison (`/descubre/regulacion`, rows grouped by `region`) reads only the hand-verified static `src/modules/content/regulation.ts`; never add or alter countries, values, dates or URLs without verification, because the section is credible only if every datum matches its cited source.
- Referral invites: `/unirse` is the only route AccessGate renders without access (`isOpenPath`). Public joins go through the `join-via-referral` function, which calls the service-role-only `referral_join` SQL function (row lock, pause/active/seat-cap checks, new access row + own code, seat increment in one transaction) and then the shared `sendAccessLink` used by `request-access`, so there is one emailer and the cap can't be bypassed. `referral_codes`/`referral_settings` are admin-only; testers read their own code via `my_referral_code()`.

- Canonical vocabulary (PriceRecord/PriceComponent, Centre/Practitioner, PatientQuote, shared with the sibling project) lives in `src/modules/canonical/` as pure adapters over the existing pricing and clinics tables, with I/O fetchers in a separate file; existing consumers and the schema stay unchanged until a deliberate migration.
- Private-beta framing is behind `FEATURES.betaBanner`: `BetaBanner` renders only in `PublicLayout`/`AppLayout` (never `WidgetLayout`), placed above the sticky header so header offsets like Descubre's `top-10` stay valid; clinic contact/booking CTAs check `shouldInterceptClinicAction()` and show `NotActiveYetDialog` (notice only, nothing sent or stored), so turning the flag off restores the original action unchanged.
- Beta navigation analytics (`src/modules/beta-analytics/`) is behind `FEATURES.betaBanner`: `logBetaEvent` passes everything through `sanitize.ts` (pathname only, identifier labels, allow-listed meta keys) so typed content can never be logged; a BEFORE INSERT trigger stamps user id/email server-side, `beta_events` reads are admin-only, and `/widgets/*` is never tracked. Admin aggregates are pure functions in `aggregate.ts`.
- Admin role management (`/admin` → "Account & admins") goes only through the `manage-admins` function: it verifies the caller with `getUser` + `has_role` in code, uses the service role server-side, refuses to promote emails without an auth account (`no_account`), and applies the pure anti-lockout rule in `manage-admins/logic.ts` (never remove the last admin; self-revoke needs `confirm_self`). Admins set only their own password client-side via `auth.updateUser`.
- Scroll-to-top + back-to-top button (`nav/PageScroll.tsx`) mount once in App; no page copies.
- Evidence geography labels/ordering (`modules/evidence/geoScope.ts`) are presentation-only; never alter figures or sources.
- `noEmailBetaJoin`: `join_direct` token redeemed by `verifyOtp`; re-entry only `no_email_join` rows, not admins.
